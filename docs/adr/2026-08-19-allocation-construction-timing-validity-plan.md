## Goal

Make `NewClient` reject negative permission-refresh cadences that would become immediate-fire timers and explicit cadences that are not nominally shorter than the TURN permission lifetime, before a successful Allocate can turn such input into a live periodic worker. This closes the post-Track-1 Allocation-construction checkpoint with one focused public-configuration invariant rather than redesigning the internal constructor bag.

## Current Shape (verified 2026-08-19 at `e57b9061efa66b979bc616834b3803cc932ecbdf`)

`ClientConfig.PermissionRefreshInterval` is a public `time.Duration`. Its comment names the wrong field, documents only the two-minute default, and declares no accepted domain (`client.go:36-53`). `NewClient` validates the caller-owned connection and canonical TURN server, defaults only a nonpositive RTO, and stores the permission interval unchanged (`client.go:129-160`). The value later crosses the sole production Allocation assembly into `client.AllocationConfig` after a successful Allocate response (`client.go:285-323`; `internal/client/allocation.go:16-35`).

`NewUDPConn` treats zero as the two-minute default and every nonzero value, including a negative duration, as the live cadence. It immediately starts the resulting periodic permission timer (`internal/client/udp_conn.go:21-28,92-157`). `PeriodicTimer` repeatedly gives that duration to `time.NewTimer`; Go timers fire immediately for a nonpositive duration, so a negative public value creates a reachable tight maintenance loop once Allocate succeeds (`internal/client/periodic_timer.go:35-68`). With no permissions the handler can return immediately and consume CPU; with permissions it can repeatedly initiate TURN maintenance work. No actual spinning timer is needed to establish or regress this construction defect.

TURN permissions have a fixed 300-second lifetime, and CreatePermission or ChannelBind resets that lifetime ([RFC 8656 Section 9](https://www.rfc-editor.org/rfc/rfc8656.html#section-9)). An explicit periodic cadence at or above five minutes is not even nominally shorter than that lifetime; exactly five minutes also leaves no scheduling or transaction margin. A sub-five-minute cadence is only a configuration condition, not a guarantee that refresh completes before expiry. The existing default of two minutes is valid. This repository intentionally uses 50 milliseconds in its end-to-end test (`client_test.go:526-548`). An immutable wiremux consumer receipt at `836f0101e99405c36af9ea9d191a849d1f35107a` shows [production zero-as-default](https://github.com/GridSwarm/wiremux/blob/836f0101e99405c36af9ea9d191a849d1f35107a/connect/pionturn/allocate.go#L19-L22) and test overrides of [250 milliseconds](https://github.com/GridSwarm/wiremux/blob/836f0101e99405c36af9ea9d191a849d1f35107a/connect/pionturn/channeldata_test.go#L16-L18) and [150 milliseconds](https://github.com/GridSwarm/wiremux/blob/836f0101e99405c36af9ea9d191a849d1f35107a/connect/pionturn/waiters_test.go#L189-L191), so an arbitrary positive minimum would break deliberate test control without closing the proven negative-duration defect.

There is one production assembler, no duplicated public validity rule, and no open issue, PR, or implementation branch for this behavior as of the audit. Track 1 removed false destination authority from Allocation construction; the remaining bag carries genuine grant and maintenance facts. Field regrouping, a builder/options layer, or a second internal validator would add seams without improving this invariant.

## Decision

`NewClient` is the single owner of the public configuration predicate: zero selects the existing two-minute default; an explicit permission-refresh interval must be positive and strictly shorter than the RFC Permission Lifetime. It accepts zero and every positive duration strictly below five minutes, and rejects negative durations, exactly five minutes, and durations above five minutes before constructing a Client. Accepted positive values cross unchanged into Allocation construction; zero remains the existing sentinel interpreted by `NewUDPConn` as the two-minute default. This universally classifies the configured duration only. It prevents negative explicit timers from reaching `time.NewTimer` and rejects cadences that are not even nominally shorter than Permission Lifetime; it does not guarantee refresh completion before expiry or bound the resource cost of caller-selected small positive durations.

The validation is deliberately at public construction rather than delayed until Allocate. A Client accepted by `NewClient` cannot later create a negative immediate-fire timer or an at/above-lifetime nominal cadence from its stored public configuration. Internal `AllocationConfig` remains an assembly type for the one production caller and package tests, not a second public validity boundary. The timing check follows the existing nil-connection and invalid-server checks, preserving their error precedence for multiply invalid configurations. The implementation returns a clear construction error consistent with those private constructor errors; it adds no exported error sentinel. The field comment is corrected to name `PermissionRefreshInterval` and document zero, the strict upper bound, and rejection.

The five-minute limit is the nominal protocol lifetime boundary, not a promise that every sub-five-minute value will succeed under scheduler stalls, network delay, server failure, process suspension, or ordinary transaction latency. Those operational failures remain owned by existing permission-refresh and Allocation lifecycle behavior. Very small positive cadences remain accepted because they are explicit caller control and support deterministic integration tests; they can be expensive, and this slice neither bounds that cost nor silently clamps, normalizes, or substitutes them.

**Rejected alternative (do not do this):** Silently replace negative or at/above-lifetime values with the default. That hides caller mistakes and makes the public configuration lie about the cadence in use.

**Rejected alternative (do not do this):** Add a positive minimum. No evidence establishes a correct product threshold, while current tests and known consumer tests deliberately use subsecond values.

**Rejected alternative (do not do this):** Validate in `NewUDPConn` as well as `NewClient`, or turn `AllocationConfig` into a validated builder/options module. There is one production assembler and one public ingress; duplicate enforcement would split ownership.

**Rejected alternative (do not do this):** Generalize the change to RTO, binding intervals, Allocation lifetime, timer construction, a broad clock, or adaptive scheduling. RTO already defaults safely when nonpositive; private test intervals and server-reported lifetime have different owners and failure contracts.

**Non-goals:** No guarantee of refresh completion before permission expiry; no resource-cost bound or positive minimum for explicit small cadences; and no timer-loop rewrite, Permission/ChannelBind attempt coalescing, Allocation constructor regrouping, builder/options layer, generic validation module, broad clock, adaptive refresh, exported error, public type addition, server-lifetime policy, network behavior, TURN bytes, retry policy, worker lifecycle, Allocation lifecycle, default-value, or positive-cadence behavior change.

## Implementation Slices

### Slice T4.S1 — Reject out-of-domain permission-refresh cadences at Client construction

**What it delivers:** One PR that adds the public construction guard in `NewClient`, corrects and completes the `ClientConfig.PermissionRefreshInterval` documentation, and adds deterministic table-driven construction evidence for every semantic duration class while preserving all accepted values.

**Implementation:** PR #81 is the slice's one intended product PR; unmentioned historical branches were not used as an implementation baseline.

**Existing-work disposition:** New work opened by the post-Track-1 evidence gate. Tracks 1–3 remain complete and are not rebaselined. The post-Track-3 attempt-coalescing checkpoint closes without code because the current Permission and binding policies still require distinct deletion, transition, worker, and lifecycle ownership.

**Blocked by:** None. PR #72 completed the only checkpoint dependency, and the defect remains reachable at the audited head.

**Single owner after merge:** `NewClient` alone owns validity of the public `PermissionRefreshInterval` value. `NewUDPConn` continues to own application of the valid zero-as-default sentinel and creation of Allocation maintenance timers. `UDPConn` remains the sole owner of permission-refresh execution and Allocation lifecycle.

**Authority completeness:** No persisted fact or restart path exists. The same slice covers the sole public constructor, the only stored copy of the public input, the sole production handoff into Allocation construction, and the destructive/resource-sensitive consumer that would otherwise start the timer. No alternate public constructor or production assembler exists.

**Transitional-seam budget:** None at merge. The intended PR cannot leave delayed public validation at Allocate, add a second duration rule in `NewUDPConn`, normalize rejected values, or retain documentation that permits an at/above-lifetime cadence.

**Blast radius:** Public `NewClient` compatibility for negative and at/above-five-minute explicit values changes from acceptance to a construction error. Zero, the two-minute default, every positive value below five minutes, the existing 50-millisecond repository test cadence, known consumer production defaults, and known consumer test cadences remain accepted. Very small accepted positives may remain resource-intensive, and a near-five-minute accepted cadence may still miss expiry because of latency; both are explicit non-goals rather than untraced guarantees. The new timing error follows the existing nil-connection and invalid-server errors in constructor precedence. No goroutine, timer, network transaction, retry, emitted byte, lock, lifecycle transition, dependency, or allocation-success path changes for accepted configurations. The bounded effect is prevention of negative immediate-fire timers and rejection of cadences that are nominally at or beyond Permission Lifetime before live work. Untraced effects are not accepted: a changed accepted cadence, changed existing-error precedence, delayed error, silent fallback, new exported API, second enforcement owner, timer rewrite, or altered Allocation behavior stops the slice.

**Artifact classification:** The `NewClient` validation guard is shipped behavior. Its negative-duration arm is required resource-safety enforcement against `time.NewTimer`'s immediate-fire behavior; its upper-bound arm is protocol-informed configuration validation, not proof of permission continuity. The field comment is shipped interface documentation, not enforcement. The table-driven constructor test and existing end-to-end cadence test are verification aids. The plan, issues, receipts, and OmniFocus tasks are process or traceability metadata. No verification aid becomes a maintained product deliverable.

**Representation contract:** Supported domain = every Go `time.Duration` value supplied through `ClientConfig.PermissionRefreshInterval` to `NewClient`, partitioned into zero, negative, positive below five minutes, exactly five minutes, and above five minutes. Go's `time.Duration` type owns the finite numeric representation; `NewClient` owns public semantic validity; RFC 8656 Section 9 owns the 300-second permission lifetime; `NewUDPConn` owns only the accepted zero-to-default interpretation. Guarantee = universal configuration classification over the complete numeric predicate: accept `d == 0 || (d > 0 && d < 5*time.Minute)` and reject every other representable duration. The guarantee does not cover refresh liveness or resource cost for accepted explicit positives. Terminating evidence = one table with representatives at negative, zero, small positive, immediately below five minutes, exactly five minutes, and above five minutes; two combined-invalid rows preserving nil-connection and invalid-server error precedence; assertions that accepted values construct successfully and rejected values return the applicable construction error; preservation of the existing 50-millisecond end-to-end cadence; reviewed source flow from public input to timer; `go test ./...`, `go test -race ./...`, `task preflight`, same-head hosted CI, and one fresh review plus at most one replacement.

**Contract closure:** Not triggered. The negative-duration consequence is materially resource-sensitive, but the accepted invariant has one public ingress, one central comparison owner, one stored value, one production handoff, and a finite integer predicate that ordinary focused table tests cover reasonably. The upper arm is a configuration rule rather than a permission-continuity guarantee. No semantic closure matrix, mutation, timing repetition, or live negative timer is required.

Preserve the existing 50-millisecond end-to-end test. Run focused constructor tests, the complete ordinary and race suites, and repository preflight. No timer instrumentation, goroutine-count assertion, mutation, fuzzing, repeated runs, platform expansion, wire fixture, or new harness is approved. Termination = the table and preservation case pass, the static flow remains single-owner, all gates pass, one fresh review and at most one replacement are complete, and no `stop-for-decision` finding remains.
