## Goal

Reshape the fork's public API to exactly what its one consumer crosses, in one idiom: `netip`-native addresses, context-first cancellation, one lifecycle object per allocation, failures surfaced as typed error values rather than log lines, prepared-only ChannelData writes, and a fork-owned integration fixture that both repositories can use. Wiremux's `connect/pionturn` composite currently reimplements canonicalization, cancellation, source filtering, and error classification around the fork's gaps; after M1 each of those becomes either unnecessary or a one-line call, and the fork's tree contains no path its consumer never exercises. The track ends with tag `v5.2.0-gs.1`.

## Current Shape (verified 2026-08-15 at `2d30274`; consumer facts at GridSwarm/wiremux `263b6a4`)

- Send-indication write path (`udp_conn.go:519-544`): `WriteTo` to an unprepared peer creates a permission on the fly, starts a bind, and sends via Send indication. The consumer never crosses this path.

Gaps wiremux built around (each maps to a slice below):

- `Allocate()` takes no context (`client.go:477`); wiremux cancels by closing its socket under the in-flight transaction and then subtracts the induced `net.ErrClosed` (`allocate.go:77,85-98,108-114`). Transaction results travel over an unbuffered channel (`internal/client/transaction.go:51,97`) whose producers delete the transaction from the map before sending (`client.go:700-711`, and `client.go:744-778` while holding `mutexTrMap`); today that is safe only because every removed transaction has a live waiter.

- `HandleInbound` performs no source admission at all (`client.go:621-625`); wiremux runs a base source guard ahead of it (`conn.go:165-206`).
- Logging is mandatory through `pion/logging` (`client.go:181-186`); wiremux ships a 12-line discard logger to keep credentials out of logs (`allocate.go:172-191`). 41 log sites exist in kept non-test code; the only ones carrying state a caller could act on are allocation-refresh failure (`allocation.go:171`, warned and otherwise ignored), permission-refresh failure (`allocation.go:182`, already terminalizes prepared bindings via `onPermRefreshFailure`), and receive-queue overflow (`udp_conn.go:739`).
- Closed-allocation errors are an unexported sentinel whose text mimics `net.ErrClosed` (`internal/client/errors.go:11`), and refresh errors wrap their cause with `%s` (`allocation.go:91,97,127`); wiremux string-matches `"use of closed network connection"` (`conn.go:624-632`) and uses the allocation `Close` result to reclassify a graceful close as forced when the socket died before the deallocation write (`conn.go:543-551`).
- Root integration tests (`client_test.go:142-236,392-484`) run against upstream `github.com/pion/turn/v5@v5.0.12` (`client_test.go:16`; `go.mod`), the transitional seam Track 1 Slice 2 introduced. Kept protocol behavior that M1 preserves byte-for-byte on the wire: Allocate challenge/response with long-term integrity (`client.go:364-474`), Refresh (`allocation.go:79-134`), CreatePermission (`udp_conn.go:678-728`), ChannelBind including the 400 recovery/close rules (`udp_conn.go:782-929`), ChannelData encode/decode, retransmission schedule (`client.go:24-38`, `transaction.go:14`), permission/binding/allocation refresh timers, `PreparePeer` coalescing and waiter-local cancellation (`udp_conn.go:198-441`), and `Close` joining allocation-owned workers after aborting in-flight transactions (`udp_conn.go:561-602`).

## Decision

- **API = the consumer's crossing, one idiom.** Public surface after M1: `ClientConfig{Server netip.AddrPort; Username, Password string; Conn net.PacketConn; RTO, PermissionRefreshInterval time.Duration}`, `NewClient(*ClientConfig) (*Client, error)`, `(*Client).Allocate(ctx) (*Allocation, error)`, `(*Client).HandleInbound(data []byte, from net.Addr) error`, `(*Client).Close()`, and `Allocation` with `RelayedAddr() netip.AddrPort`, `PreparePeer(ctx, netip.AddrPort) error`, `ReadFrom([]byte) (int, netip.AddrPort, error)`, `WriteTo([]byte, netip.AddrPort) (int, error)`, `Close() error`, plus exported error sentinels. `Client` stays a separate object from `Allocation` because the consumer owns the socket read pump and must have a `HandleInbound` target before `Allocate` returns; collapsing them would force the fork to own the pump, which the wiremux contract forbids.
- **Socket authority stays with the caller.** The fork never closes, deadlines, or otherwise interrupts `ClientConfig.Conn`. Cancellation and close are implemented by aborting the fork's own transaction waits (`abortPendingTransactionsTo`, `client.go:319`) and joining its own workers — the mechanism `4b818fc` already established. A canceled waiter may leave a transaction; producers must therefore never block on a departed waiter (buffered result channel; see Slice 3).
- **`netip` everywhere at the boundary.** Server, relayed, and peer addresses cross the API as canonical `netip.AddrPort` (unmapped, no zone, nonzero port, neither unspecified nor multicast). One unexported canonicalizer with two modes owns the rules: strict for `Server` (IPv4-mapped rejected, mirroring wiremux `validateServer`, `pionturn.go:57-75`) and unmapping for peers, inbound sources, and the server-reported relayed address (mirroring wiremux `canonicalUDPAddr`, `conn.go:208-237`). Internal permission/binding maps may stay keyed as today until Track 3.
- **`HandleInbound` admits only the configured server.** Datagrams whose canonical source differs from `Server` are ignored (nil error, no delivery); malformed protocol input from the server returns an error the caller may discard. This is defense in depth under wiremux's own guard, not a replacement for it.
- **No logging.** `pion/logging` is removed. Every log site is dispositioned in the Slice 3 ledger: dropped (debug/trace narration), already-a-value (errors already propagate to a waiter or terminalize state), or converted (allocation-refresh failure). Permanent allocation-refresh failure terminalizes the allocation with a cause — the same worker-initiated `startClose` pattern ChannelBind-400 already uses (`udp_conn.go:865-877`) — instead of being logged and forgotten. Terminalize means seal and wake, never join; `Allocation.Close` remains the caller's join point.
- **Errors are values.** Closed allocation returns `net.ErrClosed`; every wrapped cause uses `%w`; a small exported sentinel set (`ErrClosed` is `net.ErrClosed`; `ErrTransactionTimeout`, `ErrAllocationRefreshFailed`, `ErrPermissionRefreshFailed`, `ErrChannelBindFailed`, `ErrChannelBindingExpired`, `ErrInvalidPeer`, `ErrInvalidRelayedAddress`, `ErrAlreadyAllocated`, `ErrNotPrepared`) lets the consumer classify with `errors.Is`. `*stun.TurnError` continues to carry server error codes. `errors.Is(err, net.ErrClosed)` on any fork error means the fork's own closed state or a wrapped socket-close cause, never a synthetic stand-in for another failure.
- **Prepared-only writes.** `WriteTo` requires a prepared peer and emits ChannelData or fails; the Send-indication path is deleted, not guarded. The lifetime ChannelData-only invariant becomes structural: no code in the client can build a Send indication. See the [prepared-only writes ADR](2026-08-15-prepared-only-writes.md).
- **Fork-owned fixture.** A new exported package `turntest` provides a scripted in-process TURN responder covering exactly the request subset this client emits (Allocate with long-term challenge, Refresh including lifetime 0, CreatePermission, ChannelBind, ChannelData relay both ways, Data indication for permitted-but-unbound peers) with the knobs the fork's and wiremux's tests need (deny permissions, reject bind with 400, inject stale nonce, advertise an overridden relayed IP, IPv6 listen, allocation count). It replaces upstream `pion/turn/v5@v5.0.12`, which leaves `go.mod`. It is a verification aid with an example-level guarantee and no relay-quality or RFC-conformance claim. See the [fork-owned fixture ADR](2026-08-15-fork-owned-test-fixture.md).
- **Versioning.** Intermediate slices merge to `main` untagged; wiremux pins tags and is unaffected. Slice 5 tags `v5.2.0-gs.1`. Wiremux's adoption of `v5.2.0-gs.1` (skipping `v5.1.0-gs.1`, which breaks its fixture for the same reason) is consumer-side work filed as one wiremux issue by Slice 5 using the informative "Consumer adoption notes" below; it is not a slice of this program.

**Rejected alternative (do not do this):** Absorb wiremux's composite into the fork (fork-owned dedicated socket, read pump, selected-peer restriction, logical deadlines, graceful/forced close). It re-litigates the accepted wiremux socket-ownership contract that Slice 1.3 just certified and moves the terminal-ordering seam across a repository boundary; M1 makes the composite thinner, not absent. Also rejected: keeping `Listen()` and "fixing" it — the consumer owns the pump, and a second read loop with a different failure policy is a second idiom; adding `Close(ctx)`/bounded close to the fork — its close is already bounded by transaction abort, and the only unbounded case (a dead caller-owned socket) is the caller's to interrupt by contract; keeping the deadline methods "for `net.PacketConn` compatibility" — the returned type is not a `net.PacketConn` after M1 and the semantics were wrong; wiremux adopting upstream `pion/turn/v5` as its own test dependency instead of `turntest` — it moves the transitional seam to the consumer rather than removing it; merging `internal/client` into the root package — a structure refactor with no consumer-visible payoff (the mock seam is useful; Track 3 may revisit); trimming `internal/proto` (still deferred; fuzz targets and Track 3 depend on it whole).

**Non-goals:** packet-path performance (Track 3), `internal/proto` trimming, any change to the wire behavior of Allocate/Refresh/CreatePermission/ChannelBind/ChannelData, TCP/TLS transports, ICE, a bundled TURN server, wiremux-side code changes (consumer adoption is filed, not implemented, here), upstream synchronization, DNS resolution inside the fork, RFC 6156 relayed-family override (the unexported inference from `Conn.LocalAddr()` at `client.go:105-120` stays exactly as is), and touching published tags.

## Implementation Slices

### Slice 1 — Cut the client-side surface to the consumer's crossing and go netip-native at the server boundary

Retained temporarily: `Listen()` and `pion/logging` (removed by Slice 3), the `net.PacketConn` return type and deadline surface (removed by Slice 2). None widens.
