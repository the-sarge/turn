# Authenticate TURN responses before transaction completion

The transaction registry now binds every live transaction to its request method and a copied response integrity key. It accepts only success or error responses for that method and verifies MESSAGE-INTEGRITY before retiring the transaction, stopping its timer, or publishing a result. Invalid responses leave the transaction live, allowing retransmission and a later genuine response. Allocate, Refresh (including lifetime-zero release), CreatePermission, and ChannelBind all supply their long-term credential key at registration.

The sole unauthenticated exchange is the initial Allocate challenge: it must be an Allocate error with code 401 and nonempty REALM and NONCE. An authenticated 438 must carry a valid MESSAGE-INTEGRITY, the request's unchanged REALM, and a nonempty NONCE within the authenticated attributes. Accepted authenticated error responses keep the existing Allocate error handling; this change does not add Allocate retries on 438.

Attributes after MESSAGE-INTEGRITY are excluded from the attribute view published to operation consumers because they are outside the HMAC. Malformed MESSAGE-INTEGRITY lengths are rejected before invoking the dependency's fixed-size verifier. The caller's source-address admission check and transaction cancellation, abort, and retry ownership remain in place.

[RFC 8489 section 9.2.5](https://www.rfc-editor.org/rfc/rfc8489.html#section-9.2.5) requires integrity validation for ordinary authenticated responses and permits unauthenticated 401/438 challenges. This client deliberately requires signatures for all responses to authenticated requests, including those challenges, so injected errors cannot retire authenticated work or replace its nonce. Servers that omit signatures on those responses will cause retries and eventual `ErrTransactionTimeout`; deployments must use servers that sign them. A wrong-password 401 cannot verify under the client's key, so it can likewise exhaust the retransmission budget and return `ErrTransactionTimeout` instead of a 401 `*stun.TurnError`, even when the server supports signing. Configuring server signing cannot restore that wrong-password diagnostic. The initial 401 exchange remains compatible with unsigned challenges. The maintained `turntest` responder signs responses to requests whose integrity it can verify.

Regression coverage injects same-ID wrong-method, unsigned, incorrectly signed, and malformed responses across all four methods, then completes the original transaction with a valid response. Separate cases cover challenge validation, nonce poisoning, attributes after MESSAGE-INTEGRITY, copied keys, fire-and-forget retransmission, and public Allocate, PreparePeer, and periodic Refresh behavior.
